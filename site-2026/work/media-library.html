Case study 05 · Church-tech SaaS

A media library delivered as an embeddable package

The platform creates images and visual content for its client organizations, and they keep their own media too. I led the work on the library and on its most-used piece: an NPM package that brings the whole library into other products.

Industry
Church-tech SaaS
Role
Tech lead and project manager, also writing code
Team
Led a team of 3–4 developers
Key piece
Embeddable NPM package

My role and responsibilities

  • Led a small team of 3–4 developers: assigning work, reviewing code and unblocking people.
  • Acted as project manager: planning, scope, priorities and day-to-day communication with the client.
  • Owned the architecture and the main technical decisions.
  • Stayed hands-on, implementing core features myself.

Key decisions

  • Ship the library as an NPM package. People need media while working in other products, not in a separate tab.
  • Open it as a modal with its own sign-in. Any product can drop it in without rebuilding auth or UI.
  • Combine two sources in one place. Content made by the platform plus each organization's own files.

What we built

  • Media library and landing page. Serving images and multimedia to client organizations.
  • Storage for organizations. Their own media next to the platform's content.
  • The embeddable package. Sign in, browse, pick and use, inside the host product.

The hard part

Building one component that many teams and products depend on, so it has to be stable and simple to install.

What I learned

The most valuable feature was the one that left the product. Simple on its own, huge reach once embedded everywhere.

Skills shown

  • NPM package design
  • Embeddable UI
  • Auth in a modal
  • Storage
  • Reuse across products
