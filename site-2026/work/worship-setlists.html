Case study 06 · Church-tech SaaS

A Flutter app for worship setlists, with a hand-built PDF bridge

A mobile app for church worship teams to plan the songs for each event, with chord and lyric sheets from a very large music database. I led the work in Flutter, with clean architecture and one unusual piece: PDFs rendered through a bridge to HTML, CSS and JavaScript.

Industry
Church-tech SaaS
Role
Tech lead and project manager, also writing code
Team
Led a team of 3–4 developers
Stack
Flutter · BLoC · WebView
Built
By hand, pre-AI

My role and responsibilities

  • Led a small team of 3–4 developers: assigning work, reviewing code and unblocking people.
  • Acted as project manager: planning, scope, priorities and day-to-day communication with the client.
  • Owned the architecture and the main technical decisions.
  • Stayed hands-on, implementing core features myself.

Key decisions

  • Flutter with BLoC and clean architecture. UI, business logic and data kept apart from the start.
  • Bridge Flutter to a web view for PDFs. Song sheets are PDFs and had to render well in the app, so we built a two-way bridge to HTML, CSS and JavaScript.
  • Integrate the music database instead of storing sheets. Chord sheets, lyric sheets and more come from CCLI.

What we built

  • Setlist management. Add, edit, reorder songs and attach notes for each event.
  • Song sheets. Pulled from CCLI.
  • MP3 uploads. So the team can listen and rehearse.
  • In-app PDF viewer. Through the Flutter ↔ web bridge.

The hard part

Two runtimes talking to each other on one screen. The bridge was the hardest part of the project.

What I learned

A clean BLoC structure felt slow at first, and paid off the moment we had to plug in something as unusual as a web-based PDF viewer.
