Case study 07 · US retail chain

An in-store handheld app for a US retail chain

Through BuildOnline we built a replacement for the internal app that store employees of a US retail chain use on POS-like handheld devices. The client required Laravel and Hotwire, so every screen is rendered on the server inside native iOS and Android wrappers.

Industry
Retail, United States
Role
Tech lead and project manager, also writing code
Team
Led a team of 3–4 developers
Devices
In-store handhelds
Stack
Laravel · Hotwire · iOS & Android wrappers

My role and responsibilities

  • Led a small team of 3–4 developers: assigning work, reviewing code and unblocking people.
  • Acted as project manager: planning, scope, priorities and day-to-day communication with the client.
  • Owned the architecture and the main technical decisions.
  • Stayed hands-on, implementing core features myself.

Key decisions

  • Work within the client's stack constraint. Laravel and Hotwire were required, so we designed around server-rendered screens instead of fighting it.
  • Keep the logic on the server. One codebase in charge; a server change reaches every device.
  • Integrate tasks through their API. A built-in task manager that syncs with a separate API, so each employee sees their own backlog.

What we built

  • Product scanner. The main feature on the store floor.
  • Stock availability. In the current store.
  • Stock in other stores. Across the United States.
  • Inventory tools. A set of features around managing stock.
  • Employee task manager. Synced with a separate task API.

The hard part

Making server-rendered screens feel like a tool people use all day, with the scanner at the center, inside two native wrappers.

What I learned

A client constraint isn't a limit; it's the first design decision.
